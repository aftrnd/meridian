# Third-party components in the Meridian engine

The Meridian engine, `meridian-engine-arm64.tar.gz` on this repository's `v4.3.2-engine` release, is built mostly from other projects' code. This file lists that code and its licenses. The versions are the ones in `v4.3.2-engine`.

- **Source.** The source of the engine is `meridian-engine-v4.3.2-engine-source.zip`, on the same release. Its `SOURCES.txt` lists each source archive in it with where it came from, its version and its SHA-256. It also lists what the zip doesn't include, and where that source is.
- **Meridian's changes.** Meridian modifies three of the components below. Wine carries the patches in [Scripts/engine/patches/wine/](Scripts/engine/patches/wine/), 0001 to 0011 for this engine (patches with higher numbers are for later engines). DXVK carries [Scripts/engine/patches/dxvk/](Scripts/engine/patches/dxvk/), and DepotDownloader carries [Scripts/depotdownloader/meridian-task1.patch](Scripts/depotdownloader/meridian-task1.patch). Meridian doesn't change the code of anything else listed here. Packaging only rewrites library install names and the KosmicKrisp ICD's library path, marks DXVK's `d3d9.dll` as a Wine builtin DLL in its DOS stub, and signs the Mac binaries again ([Scripts/engine/package-engine.sh](Scripts/engine/package-engine.sh)). Its own files in the engine are listed at the end.
- **License texts** are in [third-party-licenses/](third-party-licenses/). Each file there is an unmodified copy of a file from the component's source as it was built, from its package, or from its upstream repository at the version used. Where a row links a text from another release, from another component or from the publisher's website, the row says so. Files named `...-linesA-B.txt` hold lines A to B of a source file, unchanged, for code whose license notice is only in that file's header.

Paths are inside the engine tarball. The tarball's own `licenses/` folder has a shorter list, and its `README.txt` says the components are dynamically loaded. Several components below are compiled into Wine's modules or into other libraries, so this file is the one to use.
